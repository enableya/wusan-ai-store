# 邀请返利原因 Mock

使用正常开发命令启动本地 5180 站点后，访问 http://127.0.0.1:5180/mock/referrals 。无需登录，可切换「商城用户视角」「管理员视角」，与实际业务复用同一个返利列表组件。

测试页由 Vite 的开发中间件提供，首次访问时使用 `tests/fixtures/referrals.ts` 创建 10 笔订单。数据仅存在于独立内存 SQLite，调用实际的邀请、建单、通知、关单、退款及登录历史判断逻辑；支付网关是完全本地替身，不加载支付配置、不访问网络。它不修改 5180 商城数据库和账号会话，也不提供付款、充值或提现操作。重启 Vite 可重建数据，生产构建和生产 API 不提供此预览入口。

| 场景 | 应看到的说明 | 实际入账 |
| --- | --- | --- |
| 有效订单付款成功 | 已入账商城余额，提现另行查看 | ¥5 |
| 等待好友付款 | 待付款，付款后预计 ¥5 | ¥0 |
| 支付超时 | 订单超过支付有效期 | ¥0 |
| 未付款关单 | 订单已关闭 | ¥0 |
| 全额退款 | 原返利已失效 | ¥0 |
| 下单前识别同设备 | 浏览器标识与账号历史识别同设备 | ¥0 |
| 邀请自己 | 邀请人与下单账号相同 | ¥0 |
| Codex 接码 | 商品不参与返利 | ¥0 |
| 邀请超过 30 天 | 长期邀请仍正常入账（兼容旧到期记录） | ¥5 |
| 付款后发现共用设备 | 同设备邀请，原新规则返利失效 | ¥0 |

初始共 10 条，已入账 2、待付款 1、不计返利 7，累计已入账 ¥10。筛选不计返利后应有 7 条、每条实际入账 ¥0；每条都有明确原因和记录时间。管理员视角另显示邀请人及完整订单号；商城用户视角使用脱敏订单号，不返回买家联系方式或设备标识。

自动验证：`npm run test:api` 包含真实仓储的原因持久化、权限/环境隔离、重复通知、重复建单和禁止双记账测试；`tests/e2e/admin.spec.ts` 中的 `referral mock shows` 用例检查用户/后台视角、过滤、刷新及 390/1440 像素布局。截图为 `artifacts/referral-reasons-390.png`、`artifacts/referral-reasons-1440.png`。
