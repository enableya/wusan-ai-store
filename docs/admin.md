# 管理后台与商品点击统计

入口为 `/admin`，使用独立管理员账号。超级管理员拥有全部后台权限，可通过「用户管理」添加管理员并修改其他账号的角色与权限。普通管理员按账号授予商品点击分析、卡密库存查看、卡密导入和支付联调权限。导入卡密同时授予库存查看权限。

## 统计口径

成功打开有效商品详情页记一次点击，包括直接通过地址访问。重新进入同一商品会计入，刷新页面、React 重复渲染和相同事件编号重试不会增加计数。管理员访问也计入，已识别的常见爬虫 User-Agent 不计入，但不能保证识别全部机器人。该数据用于衡量商品关注度，不等于真实人数或点击广告归因。

数据在 SQLite 的 `product_clicks` 表持久保存，使用服务端确定的 `production` / `sandbox` 环境。后台只展示当前站点环境的数据，按北京时间展示今日、近 7 天、近 30 天及自定义日期（最多 366 天），含点击趋势和所有商品排行。同一浏览器打开商品后，已打开的后台页面会自动刷新；后台可见时每 15 秒更新。已下架或已删除商品的历史点击保留。没有历史数据补录；功能启用之前的点击无法恢复。

访客 Cookie 使用随机值，数据库仅保存其摘要，不保存 IP、邮箱、User-Agent 或完整浏览轨迹。前端为每次访问生成随机统计编号。隐私说明同步更新。浏览器拒绝 Cookie、阻断统计请求或网络中断会影响统计完整性。

## 创建管理员

服务器首次部署后，由服务用户运行（凭据文件必须是项目目录之外的绝对路径，且尚不存在）：

```sh
sudo -u wusan env WUSAN_ENV_FILE=/etc/wusan-ai-store/production.env \
  /usr/local/bin/node /opt/wusan-ai-store/current/server/admin-cli.ts \
  create admin --credentials-file /var/lib/wusan-ai-store/.admin-initial.txt
```

命令创建超级管理员，随机生成初始密码并写入权限 `0600` 的凭据文件。指定初始密码时，用 `create USERNAME --password-stdin`，从受控输入传入密码，避免将密码放入命令参数或配置文件。相同用户名、角色和密码的初始化命令可重复执行。账号密码以 scrypt 哈希保存，登录 Cookie 为 HttpOnly / SameSite=Strict，服务器只保存会话令牌摘要，8 小时后过期；退出会立即撤销会话。

凭据应通过受控方式交付给经营方并保管在密码管理器，交付后移除服务器上的初始明文凭据文件。不要将凭据放进源码、静态目录或 Git。当前版本不提供网页重置密码功能。

## 访问源与部署

`ADMIN_ORIGIN` 设置为管理员和商城浏览器实际访问的源，例如正式上线为 `https://wusan-ai.store`，Secure Cookie 自动启用。本机 SSH 内部预览时使用 `http://127.0.0.1:5195`，HTTP 只允许回环地址；切换公开域名时同时更新该配置并重启 API。它不改变支付宝正式环境的 HTTPS 回跳及通知要求。

后台 API：

- `GET /api/admin/session`：读取当前登录状态。
- `POST /api/admin/login`、`POST /api/admin/logout`：同源登录及退出。
- `GET /api/admin/analytics/products?start=YYYY-MM-DD&end=YYYY-MM-DD`：须登录，返回汇总、趋势及排行。
- `POST /api/analytics/product-click`：匿名同源统计，参数为 `productId` 和随机 UUIDv4 `eventId`。客户端不能指定统计环境。

数据库 schema 升至 9。升级保留旧账号和已有权限，并以普通管理员角色登记；部署时使用目标环境配置初始化超级管理员。更新前先备份；如需回退，应评估更新期间新增数据后按数据库恢复流程处理。

## 验证

`npm run test:api` 包含后台鉴权、去重、时区、环境、持久化和过期会话验证。`npm run test:admin:e2e` 自动创建并清理隔离数据库，用 Chrome 验证真实访客记录与后台读取、退出登录，以及桌面和手机布局，不使用正式账号或数据库。

## 营业额统计

后台「营业额统计」需要 `revenue.view` 权限，超级管理员默认拥有该权限。报表仅查询当前服务端环境，日期按北京时间统计。付款总额按已核实付款时间计算，退款按系统首次确认成功时间计算，收支差额为同期付款减同期退款，不含成本、手续费和返利。订单概况按创建时间及当前状态统计，待付款包含已过期但尚未关单的记录。

仅能统计本系统记录的退款。升级 schema 11 时，历史退款的首次确认时间以当时保存的最后更新时间近似，之后重复查询不会改变。发布前备份数据库，并准备匹配旧数据库版本的回退方案。

### 优惠券管理

超级管理员及拥有「管理优惠券」权限的管理员可以创建、编辑、启用、停用和删除优惠码。删除后历史订单和占用记录保留，已删除的优惠码不能再次创建。优惠码可用于全店或指定商品，并可设置订单最低金额、固定优惠金额与总名额。顾客在确认购买时输入优惠码；服务端在创建订单时再次检查商品、门槛、状态和剩余名额，优惠后支付金额必须大于零。付款及退款统计使用订单实际应付金额。

为避免超发和支付宝延迟确认付款造成同一名额被重复使用，创建订单时即永久占用一个名额，包括未支付或已关闭的订单；目前不能自动释放。列表分别显示占用和已付款数量，退款也不会自动返还名额。不同运行环境的数据相互隔离。升级数据库前备份：schema 13 增加优惠券表及删除标记，旧版服务无法直接读取新版本数据库。

### 订单管理

后台的「订单管理」支持按订单号（完整或部分匹配）、订单状态、下单开始/结束日期、商品分类和具体商品组合查询。默认查看近 30 天，可选择今日、近 7 天、近 30 天或全部时间；重置筛选会查询全部订单。日期按北京时间计算，包含结束日期全天，每页 20 条，按下单时间倒序排列。

列表显示商品、分类、订单状态、金额、累计已确认退款、下单和付款时间、支付宝交易号，并标记免付开通订单和付款时间已过的待付款订单。页面首次进入时加载数据，之后通过「刷新订单」、筛选查询或翻页获取数据，不自动刷新。此操作不会主动向支付宝逐笔查单，也不会将超时待付款单直接改为已关闭。

超级管理员自动拥有访问权限；普通管理员需授予「查看订单管理」(`orders.view`) 权限。接口 `GET /api/admin/orders` 仅返回当前服务支付环境的数据，不返回查询密码、联系方式、浏览器标识或支付配置。新订单保存购买时的商品分类；旧订单使用现有商品分类，已无法关联商品的旧订单显示「未分类」。

### 开通超时订单（2026-11-08 已上线）

2026-11-09 已发布规则：付款后 30 分钟仍未开通且确认可以安全取消时，订单显示「订单已取消，退款待后台审核」。在「订单管理」之后增加独立「退款审核」菜单，默认展示全部时间的待审核记录，支持订单号与审核状态筛选、分页、手动刷新和审核历史。具有「审核订单退款」(`orders.refund`) 权限的管理员可以同意原路退款或填写原因驳回，记录审核人、时间和备注；该权限自动包含订单查看权限，普通订单查看者无法访问审核菜单或列表接口 `GET /api/admin/refunds`。订单管理只显示退款状态、备注及前往审核页面的入口，不提供直接审核按钮。退款列表仅返回当前支付环境中已有审核记录的订单。确认同意后系统再次核实上游再退款，退款成功后卡密释放回原商品库存。待审核、驳回或上游结果不明确时不退款、不释放卡密。已开通或已设置提前续费的订单保留。详见 [订单超时规则](orders.md)。

2026-11-11 已发布：退款审核列表新增「卡密」列及复制按钮，读取订单保存的履约记录，已审核或退款后仍可核对历史卡密；未分配或未记录时显示占位提示。完整卡密沿用 `vouchers.codes` 权限，超级管理员默认可见，普通管理员需同时具备退款审核与卡密查看权限；无卡密权限时服务端返回空值，页面显示「无查看权限」。此前退款列表始终隐藏卡密，本次发布不改变审核及实际退款流程。

2026-11-11 已发布：订单管理中，符合本地候选条件的免付开通订单在「复制卡密」右侧显示「回收卡密」。超级管理员默认可操作，普通管理员需授予独立 `orders.reclaim`（回收免付订单卡密）权限，自动包含订单查看和卡密查看权限。只读订单/卡密权限或删除库存权限不包含回收能力。

点击后确认订单及卡密，服务端使用共享数据库租约阻止同时验证、提交或重复回收，再向充值通道实时查询：卡密必须为 `AVAILABLE` 且商品匹配；无在途充值、已成功开通或已设置续费。已提交过的订单须核对本次已保存的上游订单号及明确终态 `NO_CHARGE`，超时、查询失败、结果不明、已使用卡密均不释放。普通付费订单、优惠后零元但非免付开通的订单、已取消、已成功及正在验证/提交的订单不可回收。

`POST /api/admin/orders/:id/reclaim-voucher` 接收 `expectedVoucherCode`，核对当前环境、权限、同源和卡密版本；查询结束后重新检查权限及占用状态。成功时在同一事务内保存回收时间/操作者、取消原订单、移除卡密占用及待确认账号。卡密按原商品、环境和优先级回库，原订单的卡密及充值邮箱保留。前后台均显示「卡密已回收」，归入已取消订单，不再允许充值；免付订单不创建退款或退款审核记录。重复操作不会再次回库或覆盖原审核人。

schema 22 为 `order_fulfillment_details` 增加可空的 `reclaimed_at` / `reclaimed_by`，不修改既有记录。发布前须备份并验证迁移，旧代码不支持 schema 22；2026-11-11 已完成正式库升级及数据保留核验；已保留兼容 schema 22 的回退版本，不可直接切回 schema 19 旧程序。

### 订单卡密与充值邮箱（2026-11-08 已上线）

订单管理新增「卡密」「充值邮箱」两列。订单查看权限可读取已验证的充值邮箱；完整卡密及复制按钮沿用「查看和复制卡密」(`vouchers.codes`) 权限，超级管理员默认可见。无卡密权限时服务端直接返回空值，前端显示「无查看权限」，不把完整卡密下发到浏览器。

充值邮箱来自成功验证的充值账号或上游确认的充值邮箱，与下单联系方式分开保存。卡密和邮箱保存在独立订单履约记录中，提交充值清空临时账号、退款取消后卡密回库，以及后续从库存移除卡密，都不会抹掉已经保存的历史记录。没有分配卡密或没有验证邮箱时显示占位提示。

schema 17 新增 `order_fulfillment_details`。迁移从现存的卡密占用和仍保留的账号信息补录历史记录；已取消且原卡密仍可核对时补录卡密。旧订单曾被清空且没有其他记录的充值邮箱无法自动恢复，会显示「未记录」，不拿联系方式替代，也不读取完整 Session 或令牌。

### 订单充值状态（2026-11-10 已发布）

订单管理在「充值邮箱」后增加独立「充值状态」列，付费和免付开通订单均展示。与前台及详情页共用状态文案和成功判定：显示未开始、待充值、排队、处理、待结算、充值成功、未扣款、待人工确认及续费情况；已取消显示已停止，取消条件尚在核实时显示取消核实中。办理完成但尚未确认结算不显示成功。

`GET /api/admin/orders` 返回最小充值摘要（是否提交、处理状态、结算状态、续费状态）和取消进度，沿用 `orders.view` 权限及支付环境隔离，不返回充值 Session、上游凭证或未经授权的卡密。点击「刷新订单」读取最新保存结果，列表不自动轮询或发起充值。长状态文案可换行，手机端沿用表格内横向滚动。

### 订单付费类别（2026-11-08 已上线）

订单列表新增「付费类别」列，筛选支持「全部类别」「免付开通」「付费开通」，可与订单号、状态、日期、商品分类和商品组合查询，统计数量及分页随筛选更新。类别由下单快照的 `staffCheckout` 标记确定：明确标记免付开通的归入「免付开通」，其余订单（含旧订单、未付款或已取消订单）归入「付费开通」，不通过金额判断类别。接口参数为 `paymentType=free|paid`，省略或空值表示全部。不需要数据库迁移。
