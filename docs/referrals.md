2026-11-14 本地待发布：取消邀请归属的 30 天限制。首次有效邀请关系长期有效，后续邀请仍不覆盖；已有邀请记录的旧到期时间不再参与读取、建单及入账判断，因此旧过期归属可用于后续新订单。接口返回 `expiresAt: null`，前端恢复邀请码不检查时间。旧数据库保留 `expires_at` 字段以兼容数据，新关系写 0，但不据此判断是否过期；本次不需要升级 schema。原已记录的历史拒绝原因保留为当时的判定，不自动补发历史返利。商城登录会话期限、订单支付时限及同设备/Codex 排除规则继续有效。仅更新本地 5180，生产尚未发布。

2026-11-14 本地待发布：schema 31 为返利保存原因代码和记录时间，付款、关单、全额退款、后续设备证据会同步更新原因。下单前已被拒绝的邀请另存访问归属，结账时保存不计返利记录，避免用户只看到空列表。有效返利与排除记录由只读视图统一展示，排除记录不参与提现余额；同一订单不可同时存在于两表。过去已被丢弃、未留下归属信息的订单无法事后重建邀请人。

用户及后台列表新增「原因 / 说明」，覆盖本人邀请、同设备、Codex 不参与、历史邀请归属过期、待付款、支付过期、关单及全额退款；记录时间随原因变化更新，重复通知及刷新不会改写相同原因的时间。待付款显示实际入账 0 与预计 5 元，失效记录显示 0，已入账明确指商城返利余额。原 5180 本地数据库已备份并升级 schema 31，副本检查 32 张既有表的原字段和业务数据未变。生产尚未发布。

2026-11-14 本地待发布：邀请返利增加同设备自邀拦截。使用现有 HttpOnly 浏览器持久标识及 `customer_browsers` 登录历史，不收集硬件指纹，不按公网 IP 直接拒绝。邀请人曾在当前浏览器使用过，或买家账号/当前浏览器的历史账号曾与邀请人在其他浏览器共用过标识时，不接受该邀请、不记录有效返利，但保留拒绝的邀请归属及订单原因。浏览器标识是浏览器数据而非物理电脑标识，换浏览器、清空全部浏览器数据且不登录既有关联账号时，不能保证识别为同一台电脑。

Codex 接码不参与返利：新订单不创建有效返利，另存不计返利的原因记录，schema 30 将已有未结算接码返利标记为 `product_excluded`，结算时重复核验商品；实际返利显示 0。升级前已入账记录保留，未付款订单和支付流程照常运行。

访问邀请链接、读取邀请归属、下单归因及异步订单入库前均核实账号/设备历史。schema 29 新增反向索引及返利记录的 `device_check_enabled`、`blocked_reason` 字段：新规则记录在付款状态变更时重新校验，后续登录补充同设备证据时，对新规则下的待付款/已入账返利标记失效，原订单与付款事实保持不变。`same_device` 失效不可被重复支付通知重新激活，返回实际返利 0 并显示「同设备邀请，不计返利」。余额沿用有效返利汇总，失效返利不计可提现金额；不会发起转账、退款或修改订单金额。

升级前已入账的历史返利标记为沿用旧规则，不因本次新增设备规则自动追溯扣减；原退款失效规则仍有效。新规则修改可能影响新增返利的可提现余额，数据库升级前须备份并核验。原 5180 本地库在副本核验 32 张表既有字段及数据不变后已升级到 schema 30；测试覆盖共用设备换账号、退出后下单、浏览器标识变化但账号历史仍可识别、异步建单中登录、下单后登录、付款后发现共用设备、重复通知及正常独立邀请。生产尚未发布本次规则。

邀请返利及提现申请/审核已部署到生产，实际转账开关保持关闭。后续修改发布仍需单独授权。商城用户与后台管理员为独立账号体系。

## 使用

- 顶部和商品详情的“分享”会重新检查登录状态。
- 未登录可登录/注册，也可直接复制不带邀请码的商品链接。
- 登录分享链接包含 `?ref=<专属邀请码>`。不会包含订单、联系方式或密码。
- 首次有效邀请在当前浏览器长期有效，后续邀请不覆盖。商城会根据服务端保存的归属，在当前页面地址自动补上 `ref`，刷新、返回首页、站内跳转、关闭后重新打开以及直接访问不带邀请码的本站地址均会恢复。其他查询参数及页面锚点保留；使用替换历史记录的方式补码，不影响返回操作。
- 地址栏以服务端实际归属为准，收到其他邀请码时仍显示有效期内首次确认的邀请码。订单归属由服务端浏览器 Cookie 和邀请记录确定，不依赖下单页面是否带有 `ref`。清除站点 Cookie、使用无痕窗口或换浏览器不属于同一浏览器记录。
- 每笔参与活动且带归属的订单由服务端保存邀请人和 500 分返利快照。已知自邀（同一商城账号或曾登录该账号的浏览器）不计入。
- 创建订单显示待好友付款；仅现有验签通知或支付宝主动查单确认付款后计入“已获得 · 待结算”。重复通知与重试不重复记账。
- 关闭/过期订单无返利；系统退款服务确认累计全额退款后失效。站外直接退款需通过系统退款查询完成核实，目前不自动同步站外退款。
- 已增加提现申请、后台审核和支付宝打款，详见 [提现管理](withdrawals.md)。累计有效返利不表示已到账，可提现余额会扣除冻结金额及已提现金额。不能识别刻意跨账号、跨设备的关联购买，正式运营结算仍需审核。
- 测试、正式数据按订单支付环境区分，测试记录不参与正式结算。参与活动的商品返利固定 5 元。Codex 接码不参与返利；其他商品未设置最低订单金额。

## 页面和权限

商城 `/referrals` 位于“我的订单”右侧，按站点环境展示对应记录。用户仅能查看自己邀请的记录，订单号脱敏，不暴露买家联系方式。
后台 `/admin?tab=referrals` 可查看当前站点环境的记录，包含邀请人、邀请码、商品、订单金额、返利金额、状态和时间，支持按状态筛选及分页。超级管理员默认可见；普通管理员需授予 `referrals.view`。

## 数据和发布

SQLite schema 10 新增客户、会话、已登录浏览器、邀请访问、订单返利表及付款/退款触发器。密码 scrypt 哈希、会话随机令牌哈希；HTTPS 使用 Secure/HttpOnly Cookie。注册/登录有同源和频率限制。当前不提供密码找回，注册者需保管登录密码。
发布前须备份数据库；schema 15 新增提现单及审核流水表，旧版服务无法打开新版数据库，回滚代码时需使用匹配的数据库备份。旧订单不追溯返利。

验证：`npm run test:api` 包含邀请归属、重复通知、无效签名、环境隔离、自邀排除、退款失效、登录退出、数据隔离和后台权限测试。浏览器测试在独立数据库进行，不触发真实收款。
